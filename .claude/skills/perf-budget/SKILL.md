# Скилл: perf-budget

Железное правило каталога №7: билд игры < 5 МБ (цель < 2 МБ), загрузка < 3 сек на 3G.
Скилл превращает это правило в измеримую проверку, которую видно до ревью, а не после
жалобы с телефона.

## Что делает скрипт

```bash
node .claude/skills/perf-budget/scripts/perf-budget.mjs            # все игры + хаб
node .claude/skills/perf-budget/scripts/perf-budget.mjs quiz jigsaw # только указанные
node .claude/skills/perf-budget/scripts/perf-budget.mjs --json      # машинный вывод для CI
```

Для каждой игры печатает: суммарный вес `dist/`, вес по gzip (так его получит телефон),
три самых тяжёлых файла и вердикт по лимитам. Возвращает код 1, если хоть одна игра
превысила жёсткий лимит — годится как шаг CI.

Игры нужно сначала собрать: `npm run build:all` (или `npm run build -w @gamewingo/<slug>`).
Скрипт честно скажет, каких билдов нет, и не будет притворяться, что всё в порядке.

## Порядок работы

1. Собрать каталог: `npm run build:all`.
2. Прогнать скрипт. Если превышение — смотреть на три самых тяжёлых файла в отчёте.
3. Типичные причины перевеса и что делать:
   - **phaser.js в каждой игре** — это нормально: он вынесен в отдельный чанк и кешируется
     браузером между играми каталога, но в бюджет одной игры входит целиком;
   - **растровые ассеты** — прогнать через скилл `asset-pipeline` (webp, нужный размер);
   - **шрифты** — не бандлить: каталог использует системный шрифт (docs/DESIGN.md);
   - **звук** — моно, 64–96 kbps, короткие эффекты (см. скилл `game-audio`);
   - **исходники в бандле** — проверить, что `terser` включён и нет `sourcemap: true` в прод-конфиге.
4. После правок пересобрать и замерить снова — в отчёте видно дельту относительно цели.

## Что скрипт не проверяет

Fps и время загрузки на реальном 3G он не меряет — это делается руками по чеклисту
скилла `webview-qa` на живом устройстве. Здесь только вес, зато точно и каждый раз.
