# SPEC: Счёт (counting)

## 1. Идентификация

- **slug** (папка / gameId): `counting`
- **Рабочее название:** Счёт / Sanoq
- **Механика в одном предложении:** детская обучающая игра — посчитать предметы на поле и нажать кнопку с нужной цифрой.
- **Возраст:** 4–7 лет (дошкольники; чтение не требуется — вопрос понятен по картинке).
- **Источник-шаблон:** официальный стартер Phaser `template-vite-ts` (через структуру `games/pairs`) — см. `docs/LICENSES.md`
- **Лицензия:** MIT (стартер); графика — векторные примитивы Phaser + системные эмодзи (ничего не бандлим)

## 2. Механика

- **Цель игрока:** ответить на 10 вопросов «сколько предметов?».
- **Управление:** тап по одной из 4 крупных кнопок-цифр (82×82 логических пикселя); mobile-first, portrait 400×720.
- **Длительность партии:** 60–120 сек (ребёнок не ограничен по времени).
- **ПРОИГРАТЬ НЕЛЬЗЯ.** Это железное правило жанра:
  - нет таймера, нет обратного отсчёта, нет проигрыша и штрафов;
  - неверный ответ НЕ завершает партию и НЕ меняет вопрос — кнопка мягко качается,
    после чего запускается **пересчёт-подсказка**: предметы по очереди подсвечиваются,
    над ними всплывают цифры 1, 2, 3… — ребёнок видит, КАК считать, и отвечает снова;
  - счёт (`correct`) при ошибке не уменьшается; ошибки влияют только на звёзды и бонус.
- **Похвала:** при верном ответе предметы подпрыгивают, летят искорки, конфетти-искорка и «Молодец!»; в конце — конфетти и звёзды.
- **Сложность:** растёт мягко по номеру вопроса (`countRange`): вопросы 1–3 → 1..5 предметов,
  4–6 → 3..7, 7–10 → 5..10 (максимум 10).
- **Варианты ответа:** всегда 4 кнопки — правильный ответ плюс соседние числа (отклонение ≤ 3,
  сначала ±1, затем ±2, ±3), без дубликатов, перемешаны. Настоящий выбор, а не «одно очевидное число».
- **Предметы:** одинаковые эмодзи (🍎 🦆 ⭐ 🐟 🎈 🍓 🐝 🌸 🍌 🐞), разложены аккуратной
  сеткой по таблице раскладок (1..10 предметов), без наложений.
- **Как считается score:** `correct * 100 + (mistakes === 0 ? 300 : mistakes <= 2 ? 100 : 0)` — см. `src/core/score.ts`.
- **Максимально возможный score:** **1300** (10 верных + бонус 300 за партию без ошибок) — для серверного антифрод-лимита.
- **Антифрод (сервер):** score > 1300 — невозможен; `meta.correct` ≤ 10, `meta.mistakes` ≥ 0;
  минимальная правдоподобная длительность партии ≈ 10 сек (10 вопросов), нулевая/микроскопическая
  `durationMs` при score 1300 — повод отклонить результат.
- **Звёзды:** 3 — без ошибок, 2 — до двух ошибок, 1 — партия пройдена (даётся всегда).
- **Прогресс:** лучший результат в localStorage (`counting:best`), флаг обучения — `counting:onboarded`.

## 3. Бренд и локализация

- **Палитра:** светлая тема WinGo (персиковый фон #fbebe1, primary #f26522) — общая для каталога,
  `theme.primary`/`background` применяются из INIT; поле — белая карточка, цифры пересчёта — оранжевые,
  похвала — зелёная (#2fb84c).
- **Шрифты:** Rubik (бандл, сабсеты latin + cyrillic).
- **Чёткость (DPR):** холст рендерится в `DPR` (≤3) раз плотнее логических 400×720,
  камера каждой сцены — `setupCamera()`, каждому тексту — `setResolution(DPR)`.
- **Маскот / ключевой арт:** 🔢 в меню; предметы — системные эмодзи, кнопки и поле — вектор.
- **Языки:** RU / UZ, все строки через `src/i18n` (`ru.json` / `uz.json`, парность ключей под тестом).
- **Сплэш-экран:** нет (мгновенная загрузка), Boot ждёт INIT ≤700 мс.

## 4. Обучение

Три шага поверх НАСТОЯЩЕГО поля (`src/game/onboarding.ts`), с блокировкой тапов:

1. подсветка поля с предметами — «Посчитай, сколько тут предметов»;
2. подсветка ряда кнопок-цифр — «Нажми внизу цифру — сколько насчитал»;
3. реальный запуск пересчёта (та же анимация, что и после ошибки) — «Ошибся? Не страшно:
   покажем, как считать, и попробуешь снова».

Показывается один раз при первой партии (`counting:onboarded`) и по кнопке «Как играть» из меню.

## 5. Финтех-слой (события моста)

- [x] `GAME_READY` — при загрузке (Boot)
- [x] `GAME_START` — при старте партии (`session.start()`)
- [x] `GAME_OVER` — в конце партии со `score` и `durationMs`
- [x] `GAME_EXIT` — по ссылке «‹ К играм» в меню (`session.exit()`)
- [ ] `REWARD_CLAIM` — нет (нет daily-механики)
- [x] `GAME_EVENT` — `round_finished {correct, mistakes}`

Сервер получает `submitScore` c meta `{correct, mistakes}` — начисление и валидация только на сервере.
Игра баллы не начисляет и реальных денег не показывает.
