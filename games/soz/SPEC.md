# SPEC: «5 harf» / «5 букв» (Wordle-механика)

> Заполнено на основе брейншторма. Механика внутри команды — «Wordle»; публично название Wordle
> НЕ используем (товарный знак NYT). Продуктовый бренд: «5 harf» (UZ) / «5 букв» (RU).

## 1. Идентификация

- **slug** (папка / gameId): `soz`
- **Рабочее название:** «5 harf» (UZ) / «5 букв» (RU)
- **Механика в одном предложении:** угадать слово из 5 букв-юнитов за 6 попыток, подсветка «есть/на месте/нет».
- **Источник-шаблон:** `template-vite-ts-main` (официальный Phaser-стартер) — см. запись в `docs/LICENSES.md`
- **Лицензия:** MIT (стартер). Словари — отдельными строками в реестре по мере добавления источников.

## 2. Механика

- **Цель игрока:** отгадать загаданное слово из 5 букв-юнитов за ≤6 попыток.
- **Управление:** тап по экранной клавиатуре (mobile-first, portrait). Физическая клавиатура — опционально в вебе.
- **Длительность партии:** ~60–120 сек (не лимитируется в UI; серверный лимит времени сессии — антифрод).
- **Как считается score:**
  - не угадал → `score = 0`;
  - угадал → `score = max(0, 10000 − guessesUsed×1000 − min(durationSec, 999))` (клампим в ≥0).
  - Ранжирование лидерборда: score монотонен относительно (попытки↑ хуже, время↑ хуже), поэтому
    сортировки «по score» и «по (попытки, время)» совпадают — сервер ранжирует **по score** (одна метрика).
- **Максимально возможный score:** **9000** — угадал с 1-й попытки мгновенно: `10000 − 1×1000 − 0`.
  Это серверный антифрод-потолок. (`min(durationSec,999)` — только нижняя граница добавляемого штрафа;
  на потолок не влияет.)
- **Прогресс/уровни:** нет уровней. Прогресс = стрик (подряд решённые дни, считает сервер) + лидерборд.

### 2.1. Диграф-движок (ключевая особенность)

- `tokenizeWord(word, locale): Unit[]` режет слово на **буквы-юниты**.
  - `ru`: юнит = один символ. **`ё` нормализуется в `е`** (на вводе и в словарях) — игроку не нужна
    отдельная клавиша `ё`, ввод прощающий. В словарях `ё` не хранится.
  - `uz` (латиница): жадно склеивает диграфы `oʻ`, `gʻ`, `sh`, `ch`, `ng` в один юнит; остальное — по символу.
- Слово валидно, если `tokenize(word).length === 5 && dictionary.has(normalize(word))`.
- Вычисление цветов (`evaluate`) идёт **по юнитам**, а не по символам (иначе `sh` подсветится как `s`+`h`).
- `ʻ` — символ U+02BB (modifier letter turned comma), не ASCII-апостроф. Нормализовать ввод (`'`, `’`, `ʼ`, `` ` `` → `ʻ`); нижний регистр.
- **Жадный разбор — единственный авторитет.** Клавиатура `uz` имеет отдельные клавиши-диграфы
  (`Oʻ Gʻ Sh Ch Ng`), но и последовательность `s`+`h` токенизатор всё равно склеит в юнит `sh`.
  Значит слова, где `s`+`h` (или `n`+`g`, `c`+`h`) должны быть **двумя** юнитами, в MVP не поддерживаются —
  ответы курируются так, чтобы такой неоднозначности не было. Backspace удаляет **целый юнит** за один тап
  (стёр `sh` — исчез весь диграф).

### 2.2. Режимы

- `daily` — слово дня, детерминированно от `dayId`; шлёт `submitScore()` → награда; 1 награда/день (сервер).
- `practice` — слово из списка ответов, выбранное псевдослучайно (не равно сегодняшнему daily);
  `GAME_OVER` для аналитики шлётся, но `submitScore()` НЕ вызывается (без начисления).
- **`dayId` (пин, клиент == сервер):** `dayId = floor((Date.now() + 5*3600*1000) / 86400000)` —
  дни по таймзоне **Asia/Tashkent** (UTC+5, без DST с 1992). Сервер обязан считать так же.
- **Индекс слова дня (пин, клиент == сервер):** детерминированный 32-битный хэш от `dayId`:
  `h = dayId>>>0; h = Math.imul(h ^ (h>>>16), 0x45d9f3b); h = (h ^ (h>>>16))>>>0; index = h % answers.length`.
  MVP допускает повторы слов (гарантируется только детерминизм; критерий теста — воспроизводимость).
- **Локаль фиксирована из `INIT`** — в MVP нет внутриигрового переключателя языка (убирает рассинхрон
  «слово дня/награда» между языками). RU и UZ на один `dayId` решают разные слова (у каждого свой список).

### 2.3. Персистентность и анти-реплей (клиент)

- Состояние daily-партии сохраняется в `localStorage`, ключ `soz:<locale>:<dayId>`: ряды, статусы,
  завершено/решено, `rewardClaimed`.
- Повторно открыл WebView в тот же день → доска восстанавливается; завершённое daily **нельзя переиграть
  ради награды** (клиентский guard) — сервер дополнительно держит лимит 1 награда/день/пользователь.
- `practice` состояние не персистится (или отдельным ключом без наградной логики).
- `PAUSE`/`RESUME` из моста: пауза останавливает игровой таймер (для `durationMs`), resume восстанавливает.

## 3. Бренд и локализация

- **Палитра:** дефолтная тёмная а-ля Wordle (green `#538d4e`, yellow `#b59f3b`, grey `#3a3c42`), поверх — `theme` из `INIT` (primary/secondary/background/logoUrl).
- **Шрифты:** бандлим шрифт с покрытием кириллица + латиница + `ʻ` (U+02BB), сабсетим под используемые глифы (бюджет билда).
- **Маскот / ключевой арт:** минимально; акцент на типографику и плитки. Иконки — по необходимости (Kenney/AI), с записью в LICENSES.
- **Языки:** RU / UZ-латиница (EN — вне рамок MVP). Все строки — через `i18n/<loc>.json`, без хардкода.
  Клавиатура и алфавит выбираются по локали из `INIT`; внутриигрового переключателя языка в MVP нет.
- **Сплэш-экран:** лого клиента из `theme.logoUrl` (ленивая загрузка; фолбэк — брендовый заголовок игры).

### 3.1. Раскладки клавиатуры

- **RU** (ЙЦУКЕН, без `ё`): `й ц у к е н г ш щ з х ъ` / `ф ы в а п р о л д ж э` / `ВВОД я ч с м и т ь б ю ⌫`.
- **UZ** (QWERTY + диграфы): `q w e r t y u i o p` / `a s d f g h j k l` / диграфы `oʻ gʻ sh ch ng` /
  `ВВОД z x c v b n m ⌫`. Клавиши-диграфы вводят юнит целиком; `⌫` удаляет юнит целиком.

### 3.2. Доступность

- Не полагаться только на цвет: переключатель high-contrast палитры (оранжевый/синий) + значок-статус на
  плитке; тап-таргеты клавиш ≥ 40px; поддержка масштаба шрифта ОС.

## 4. Финтех-слой (события моста)

- [x] `GAME_READY` — при загрузке (обязательно)
- [x] `GAME_START` — при старте партии (нужен для серверного лимита времени)
- [x] `GAME_OVER` — в конце со `score`, `durationMs`, `meta`
- [x] `REWARD_CLAIM` — кнопка «Забрать награду» (только `daily`, решённое слово)
- [x] `GAME_EVENT` — аналитика: `guess_submitted`, `mode_selected`, `share_result`, `invalid_word`

- **`meta` в `GAME_OVER`:** `{ mode: 'daily'|'practice', dayId, locale, guessesUsed, solved, rows }`,
  где `rows: { units: string[]; statuses: ('correct'|'present'|'absent')[] }[]` — полная история попыток
  (юниты + паттерн статусов) для серверной проверки правдоподобности.
- **`durationMs`:** измеряется от `GAME_START` до `GAME_OVER` (пауза не считается).
- **submitScore:** вызывается ТОЛЬКО для `mode === 'daily'`. Для `practice` — нет.
- **Порядок награды (устраняет двойное начисление):**
  1. `submitScore()` → сервер **валидирует** и возвращает `{ accepted, pointsAwarded }` — это **превью**
     (сколько будет начислено), баллы ещё не зачислены.
  2. Кнопка «Забрать награду» → `REWARD_CLAIM` → сервер **фактически зачисляет** → `REWARD_RESULT { granted, points }`.
  - Авторитет начисления — `REWARD_CLAIM`/`REWARD_RESULT`; `submitScore` только считает и резервирует.
- **Баллы/награды:** сумму и правила решает бэкенд; игра только шлёт факты.
- **Лидерборд:** есть, по слову дня, ключ **per-locale** (`api.leaderboard('soz')` с фильтром локали на
  сервере, т.к. слова разные) — RU и UZ ранжируются раздельно.
- **Награда — 1/день/пользователь** независимо от языка (игра в оба языка ≠ две награды; enforce на сервере).
- **Стрики:** есть; счёт подряд решённых дней ведёт сервер, UI показывает 🔥.
- **Шэринг результата:** эмодзи-грид (🟩🟨⬛) + заголовок БЕЗ слова «Wordle». В WebView запись в буфер
  часто заблокирована → основной путь — `GAME_EVENT('share_result', { text })`, хост-приложение делает
  нативный share; фолбэк — `navigator.clipboard`, если доступен.
- **Подтверждение существования событий:** `GAME_EVENT` и `GAME_ERROR` присутствуют в
  `@gamewingo/game-bridge` (`bridge.track()` / `bridge.error()`) — проверено по контракту `events.ts`.
