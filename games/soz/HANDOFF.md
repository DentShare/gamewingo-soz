# Передача игры «5 harf / 5 букв» (slug: `soz`) тех.отделу WinGo

Казуальная игра-угадайка слов (механика Wordle) для встраивания в **WebView** приложения WinGo.
RU + UZ (латиница). Готова к просмотру и интеграции.

---

## 1. Как посмотреть / поиграть (без интеграции)

Игра — статический билд (HTML/JS), работает автономно в **демо-режиме** (локальные баллы/стрик/
лидерборд), если приложение не прислало данные. Три способа:

- **По ссылке (проще всего):** открыть задеплоенный URL в браузере телефона. _(URL появится после
  деплоя на Vercel — см. §4; вписывается в `games/manifest.json`.)_
- **Локально из исходников:**
  ```bash
  npm install
  npm run bridge:build
  npm run dev -w @gamewingo/soz      # откроется http://localhost:<порт>
  ```
- **Готовый билд:** папка `games/soz/dist/` — отдать любым статическим сервером
  (`npx serve games/soz/dist`) или залить на хостинг.

В демо: **Тренировка** — играть без лимита; **Слово дня** — одно слово в сутки (детерминированное).

## 2. Что должен сделать тех.отдел (интеграция)

Игра — **клиент**. Она НЕ начисляет баллы — только сообщает факты. Начисление, валидация, лидерборд,
стрики и антифрод — **на стороне сервера WinGo**.

### 2.1. Встроить в WebView и прислать INIT

Игра при загрузке шлёт `GAME_READY`. В ответ приложение должно прислать `INIT`:

```ts
{
  type: 'INIT',
  authToken: string,      // Bearer-токен для вызовов API
  apiBaseUrl: string,     // база бэкенда WinGo
  locale: 'ru' | 'uz',    // язык
  sessionId: string,      // id игровой сессии (для антифрода)
  theme?: {               // брендовая тема (необязательно)
    primary, secondary, background, fontFamily?, logoUrl?
  }
}
```

Транспорт моста уже поддерживает **iOS WKWebView** (`webkit.messageHandlers.gameBridge`),
**Android WebView** (`AndroidBridge.onGameEvent`) и веб-фолбэк (`postMessage`). Контракт — в пакете
`packages/game-bridge` (`src/events.ts`).

### 2.2. События, которые шлёт игра приложению

| Событие | Когда | Данные |
|---|---|---|
| `GAME_READY` | загрузка | `protocol` |
| `GAME_START` | старт партии | `sessionId` |
| `GAME_OVER` | конец партии | `score`, `sessionId`, `durationMs` |
| `REWARD_CLAIM` | «Забрать награду» (daily) | `rewardId`, `sessionId` |
| `GAME_EXIT` | тап «‹ К играм» в меню | `sessionId` — приложение возвращает WebView к каталогу игр |
| `GAME_EVENT` / `GAME_ERROR` | аналитика / ошибки | — |

Плюс прямой вызов API (Bearer-токен):
- `POST /games/score` — `{ sessionId, gameId:'soz', score, durationMs, meta }`,
  где `meta = { mode, dayId, locale, guessesUsed, solved, rows }` (`rows` — паттерн статусов для проверки).
  Ответ: `{ accepted, pointsAwarded }` (превью).
- `GET /games/soz/leaderboard?limit=N` — топ (фильтр по локали на сервере).

### 2.3. Что реализовать на сервере

- **Валидация score** и антифрод: лимит времени сессии, **max score = 9000**, `dayId` = текущий день
  по таймзоне **Asia/Tashkent** (`floor((now+5ч)/24ч)`), паттерн `meta.rows` правдоподобен.
- **Начисление баллов** — по `REWARD_CLAIM` → ответить `REWARD_RESULT { rewardId, granted, points }`.
  `submitScore` только валидирует/резервирует, фактическое зачисление — на `REWARD_CLAIM`.
- **1 награда в день** на пользователя (независимо от языка).
- **Стрик** (подряд решённые дни) и **лидерборд** (per-locale).
- **Формула score (справочно):** `solved ? max(0, 10000 − попытки×1000 − min(сек,999)) : 0`.

### 2.4. Управление из приложения

- `PAUSE` / `RESUME` — игра ставит на паузу таймер (при сворачивании WebView).
- `REWARD_RESULT` — результат начисления (см. выше).

- **Движок:** Phaser 4 (MIT) · **Сборка:** TypeScript + Vite · **Хостинг:** статический билд (Vercel).
