# SPEC: Башня (stack)

## 1. Идентификация

- **slug** (папка / gameId): `stack`
- **Рабочее название:** Башня / Minora
- **Жанр:** аркада (без уровней сложности, партия 30–90 сек, мгновенный рестарт)
- **Механика в одном предложении:** роняешь едущий блок на вершину башни; всё, что свесилось за край, отрезается.
- **Источник-шаблон:** официальный стартер Phaser `template-vite-ts` (через структуру `games/pairs`) — см. `docs/LICENSES.md`
- **Лицензия:** MIT (стартер); графика — векторные примитивы Phaser (Rectangle/Graphics), ассеты не бандлятся

## 2. Механика

- **Цель игрока:** построить башню как можно выше, не теряя ширину.
- **Управление:** тап в любом месте поля ниже HUD (или `Space` на десктопе) — блок падает.
  Mobile-first, portrait 400×720, ни одного элемента мельче 40 px по высоте.
- **Ход партии:**
  1. Текущий блок ездит горизонтально над вершиной и отражается от краёв поля.
  2. Тап фиксирует блок. Перекрытие с блоком снизу становится новой шириной;
     свес отрезается, визуально отваливается и падает вниз.
  3. Промах ≤ 4 px — идеальное попадание: ширина НЕ уменьшается, вспышка, надпись «Точно!» и бонус к очкам.
  4. Перекрытия нет → башня рушится, партия мгновенно окончена.
- **Скорость:** `min(0.46, 0.16 + 0.0065 × блоков)` px/мс — растёт с высотой, есть потолок.
- **Камера:** после 17 блоков башня плавно уезжает вниз, вершина держится примерно на одной высоте экрана.
- **Длительность партии:** 30–90 сек (обрывается мгновенно при промахе).
- **Уровни сложности:** нет — одна кнопка «Играть». Сложность растёт внутри партии.
- **Прогресс:** рекорд партии в localStorage (`stack:best`), флаг обучения — `stack:onboarded`.

## 3. Счёт

- **На экране** (`core/stack.ts`): установленный блок = 1 очко, идеальное попадание = ещё +1.
- **Для сервера** (`core/score.ts`): `score = blocks × 100 + perfects × 50`.
- **Максимально возможный score:** ограничен константой `MAX_SCORE = 100 000`
  (≈1000 блоков подряд — практически недостижимо). Всё выше — повод отклонить результат.
- **Дополнительные проверки на сервере:** `perfects ≤ blocks`; `durationMs` ≥ ~0.5 сек на блок
  (быстрее физически не натапать); частота отправок с одного `sessionId`.
- **Начисление баллов — только на сервере.** Игра ничего не начисляет и не хранит баланс.

## 4. Ядро и тесты

- `src/core/stack.ts` — чистая логика (движение, отражение, обрезка, идеальные попадания, конец игры),
  RNG инжектируется (`seed` или готовый `rng`), никакого Phaser/DOM.
- `src/core/stack.test.ts` — перекрытия, обрезка, конец игры, отражение от краёв, рост скорости, детерминированность по seed.
- `src/i18n/i18n.test.ts` — парность ключей RU/UZ.
- `src/game/roundTimer.test.ts` — учёт пауз в длительности партии.

## 5. Бренд и локализация

- **Палитра:** светлая тема WinGo (персиковый фон #fbebe1, primary #f26522) — общая для каталога,
  `theme.primary`/`theme.background` применяются из INIT. Блоки — плавный градиент оттенков (`blockColor`).
- **Шрифты:** Rubik (бандл, сабсеты latin + cyrillic), прогрев до старта Phaser.
- **Языки:** RU / UZ, все строки через `src/i18n` (переключатель в меню).
- **Сплэш-экран:** нет (мгновенная загрузка), Boot ждёт INIT ≤ 700 мс, иначе демо-режим.

## 6. Обучение

Три шага поверх настоящего поля (`src/game/onboarding.ts`), ввод заблокирован:

1. `onboarding.drop` — подсвечена полоса, по которой ездит блок (он продолжает ехать).
2. `onboarding.cut` — блок РЕАЛЬНО падает с небольшим промахом, подсвечен отрезанный край.
3. `onboarding.score` — подсвечен счётчик очков.

Показывается один раз при первой партии (флаг `stack:onboarded`) и по кнопке «Как играть» из меню.
После обучения в реальной партии башня сбрасывается — играем с чистого листа.

## 7. Финтех-слой (события моста)

- [x] `GAME_READY` — при загрузке (Boot)
- [x] `GAME_START` — при старте партии (`session.start()`)
- [x] `GAME_OVER` — в конце партии со `score` и `durationMs`
- [x] `GAME_EXIT` — по ссылке «‹ К играм» в меню
- [ ] `REWARD_CLAIM` — нет (нет daily-механики)
- [x] `GAME_EVENT` — `round_finished {blocks, perfects}`
- [x] `PAUSE`/`RESUME` — таймер партии исключает время в свёрнутом WebView

Сервер получает `submitScore` c `meta: {blocks, perfects}` — валидация и начисление только на сервере.

## 8. Производительность

- Прямоугольники блоков переиспользуются из пула: за кадр не создаётся и не уничтожается ни одного объекта,
  в `update()` меняется только `x` текущего блока.
- Одновременно на экране ≤ ~32 игровых объектов (19 видимых блоков + текущий + падающие куски + HUD).
- Ассеты не грузятся вообще (векторные примитивы + системный шрифт), билд — только код.
