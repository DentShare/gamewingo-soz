# Аналитика каталога

Кто как играет, где бросает и сколько это стоит в баллах. Считается в нашем
Score Engine по тому, что он и так получает от игр; наружу не уходит ничего.

## Где смотреть

```
<адрес бэкенда>/analytics/ui
```

Страница мобильная — открывается с телефона. Если в окружении задан `ADMIN_TOKEN`,
его нужно один раз вписать в поле наверху: он сохранится в браузере.

Пока боевого трафика нет, на странице кнопка «Показать на демо-данных» — она
заполняет хранилище сгенерированным набором, чтобы было видно, как всё выглядит.
Демо-данные помечены оранжевой плашкой и стираются одной кнопкой.

## Почему не PostHog, GA4 и не SDK в играх

Три причины, и ни одна не про вес библиотеки:

1. **Данные не покидают периметр.** Это поведение пользователей банковского
   приложения. Закон Узбекистана о персональных данных требует хранить данные
   граждан в базах на территории страны; накрывает ли он игровую телеметрию —
   вопрос к юристам, но выяснять его лучше до отправки, а не после.
2. **Труба уже наша.** Игра шлёт события и итог партии в Score Engine через мост.
   Не хватало только записи и агрегатов — вендор здесь ничего не добавляет.
3. **WebView.** Внешний SDK — вторая сетевая зависимость внутри чужого приложения,
   со своими таймаутами, куками и блокировками.

Если позже понадобится готовый интерфейс продуктовой аналитики, те же события
пересылаются в PostHog **с бэкенда**, обезличенным хешем и одним флагом
окружения. Игры при этом не меняются.

## Что считается

| Показатель | Как считается | Зачем |
|---|---|---|
| Игроки за период | уникальные `user_id` из партий, событий и заходов | масштаб |
| Партии | завершённые обращения `/progression/result` без отказа | объём игры |
| Начислено | сумма положительных записей аудита за период | стоимость мотивации |
| Медиана партии | медиана `durationMs` | длинная игра или перекур |
| Отсеял антифрод | доля отклонённых обращений | здоровье правил |
| Воронка игры | зашли → доиграли → прошли хотя бы раз → вернулись в другой день | где теряем |
| Докуда доходят | максимальный пройденный уровень на игрока | где стена |
| Тяжёлые уровни | проходимость по каждому уровню (от 3 попыток) | что чинить |
| D1 / D7 | доля вернувшихся на следующий и седьмой день от когорты первого дня | возвращаемость |
| Экономика | начисления по причинам, отказы по причинам | куда уходят баллы |

Все дни — по календарю Ташкента (UTC+5), тем же расчётом, что `computeDayId`
в клиенте. Медиана, а не среднее: одна двухчасовая партия не должна сдвигать
картину.

### Одна цифра — один источник

Баллы во всех блоках берутся из аудита начислений. Поэтому «Начислено» в итогах,
сумма по играм плюс чек-ины и «Начислено, всего» в экономике совпадают всегда.
Это проверяется тестом `test_points_agree_between_totals_and_economy` — если
однажды разойдётся, тест упадёт раньше, чем это увидит человек.

Разница между суммой по играм и общим итогом — чек-ины: они не привязаны к игре.

## API

Все под тем же `X-Admin-Token`, что и админка баланса.

```
GET  /analytics/summary?days=14[&game=snake]   всё для страницы одним запросом
GET  /analytics/overview?days=14               итоги и активность по дням
GET  /analytics/games?days=14                  таблица игр
GET  /analytics/funnel/{game}?days=14          воронка игры
GET  /analytics/levels/{game}?days=30          уровни: попытки, проходимость, отвал
GET  /analytics/retention?days=14              D1 и D7
GET  /analytics/economy?days=14                начисления и отказы
POST /analytics/demo?days=21&players=160       заполнить демо-данными
DELETE /analytics/data                         стереть накопленное
```

## Что должно случиться, чтобы пошли настоящие цифры

1. **Score Engine поднят.** Railway: Root Directory = `backend`, переменные
   `ADMIN_TOKEN` и `GAMEWINGO_ORIGINS`.
2. **Приложение отдаёт адрес API.** Игра берёт его из `INIT.apiBaseUrl` через мост;
   в автономном вебе там заглушка `demo://local`, и на сервер ничего не уходит.
3. **Игры перешли на `submitResult`.** Сейчас `session.finish` зовёт старый
   `submitScore` — воронка и уровни наполнятся после перевода.

До этого страница живёт на демо-данных и честно об этом говорит.

## Хранение

Демо-режим держит факты в памяти процесса с потолком 200 000 строк на вид
(старые вытесняются). Для продакшена — `backend/migrations/002_analytics.sql`:
три плоские append-only таблицы и витрина по дням. Схема не меняется при
добавлении нового показателя: показатели считаются на чтении.
