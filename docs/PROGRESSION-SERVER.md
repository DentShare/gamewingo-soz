# Событийная прогрессия: серверный слой

Как каталог переезжает с демо-кошелька на серверное начисление. Клиентская
лестница уровней и звёзды описаны в `docs/PROGRESSION.md` — этот документ про
то, что происходит после того, как партия сыграна.

## Принцип

Игра **не начисляет баллы** (железное правило №1). Она отправляет:

1. **сырые события** по ходу партии — `bridge.sendEvent({ game, name, sessionId, meta })`;
   мост копит их и шлёт пакетом `GAME_EVENTS` раз в 250 мс;
2. **финальный результат** — `bridge.sendResult({ game, mode, level, score,
   durationMs, sessionId, won, metrics })` → событие `GAME_RESULT`.

Сервер (FastAPI, `backend/`) по конфигу игры превращает события в баллы,
судит звёзды по goals уровня, закрывает задания дня и достижения, применяет
антифрод — и отвечает событием `PROGRESS_RESULT` (xp, звёзды, баланс, новые
достижения). Клиент только показывает эти числа.

## Один источник истины

```
packages/game-progress/src/config/   ← правила: скоринг, звёзды, задания,
                                        достижения, антифрод (TypeScript)
games/<slug>/src/core/levels.ts      ← реальные лестницы уровней игр
packages/game-progress/src/bonus.ts  ← тарифы кошелька (TARIFF)
        │
        │  npm run progression:export
        ▼
backend/app/progression/configs/*.json   ← 11 игровых конфигов + catalog.json
        │
        ▼
FastAPI Score Engine  ←──  override из админки (Supabase, без релиза)
```

Скрипт экспорта бандлит `levels.ts` каждой игры и подшивает лестницу в JSON —
у сервера те же 15 уровней и пороги звёзд, что видит игрок, без ручного
дублирования. Потолок очков берётся из `MAX_SCORE`/`SCORE_CAP` игры, если она
его объявляет.

## Экономика — одна на клиент и сервер

Тарифы каталога (`catalog.json`) собираются из живых констант демо-кошелька:
чек-ин 5→10→…→25 с серией, первое прохождение уровня `20 + 2×(n−1)`,
задание дня 15, слово дня 25. Идемпотентные ключи наград на сервере совпадают
с клиентскими (`level-<slug>-<n>`, `soz-daily-<dayId>`, `checkin-<dayId>`…) —
при переезде с витрины на сервер игрок видит те же цифры, и ничего не
начисляется дважды.

Поверх экономики каталога у каждой игры есть свой серверный слой: событийный
скоринг (`pair_found`, `tile_merged`…), задания дня игры и её достижения —
это посев баланса, который компания крутит в админке.

## Осознанные отличия от исходного ТЗ

Исходный документ писался без доступа к репозиторию; при внедрении:

- **Уровни не переопределяются в конфигах.** ТЗ предлагало «15 уровней»
  таблицами в центральном конфиге (для soz — слова из 4/6 букв, для детского
  судоку — 9×9). Словарь «5 букв» пятибуквенный, судоку детское — такие уровни
  невозможны; а главное, лестницы уже смержены и работают. Источник истины —
  `games/<slug>/src/core/levels.ts`, экспорт подшивает их автоматически.
- **Звёзды уровня — по goals уровня,** как на экране итога, а не по одному
  глобальному порогу на игру. Глобальные пороги остались запасными
  (`starsFallback`) для слова дня и бесконечного режима.
- **Метрики звёзд сверены с играми:** sorting/counting судятся по ошибкам
  (в ТЗ было время), sudoku — по секундам, 2048 и аркады — по очкам.
- **Починены правила-пустышки** (`base: 0` без `perItemKey` всегда даёт ноль);
  валидатор админки такие конфиги не пропускает.
- **Единый баланс вместо параллельной экономики.** ТЗ вводило свои цифры
  «с нуля»; тарифы каталога взяты из уже показанного пользователю
  демо-кошелька, событийный скоринг добавлен поверх.
