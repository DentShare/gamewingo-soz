# Анонимный мониторинг прогона

Монитор работает для всего каталога `https://gamewingo-soz.vercel.app`: игроки
за период и по дням, недавняя активность, активное время, завершённые партии,
начисленные демо-коины, таблица анонимных игроков, отдельные партии
(время, игра, счёт и длительность) и две выгрузки CSV.
Ссылок и кнопок отчёта в игре нет.

## Удержание и воронка

Закрытый маршрут `/monitor/analytics?days=14` и разделы в отчёте показывают:

- **DAU / WAU / MAU**: уникальные браузеры с положительным активным временем
  или завершённой партией за сегодня / последние 7 / 30 дней, включая сегодня.
  Нулевые heartbeat скрытых и простаивающих вкладок не считаются активностью.
- **Новые / прежние за выбранный период**: активные в нём браузеры, впервые
  активные в этом периоде / раньше него. Первый день определяется по всей
  сохранённой истории, а не по началу выбранного окна.
- **D1 / D7 / D30**: точный календарный возврат на 1-й / 7-й / 30-й день после
  первого наблюдаемого активного дня, по Ташкенту. В знаменатель входят только
  игроки, для которых соответствующий день уже полностью закончился. Текущий
  незавершённый день исключается даже при уже полученном возврате. Если таких
  игроков нет, процент равен `null` и показано «Ещё рано», а не 0%.
- Карточки удержания учитывают **все наблюдаемые зрелые когорты**. Таблица когорт
  показывает группы с первым активным днём **в выбранном периоде**. Это явно
  подписанные разные срезы. Первый наблюдаемый день не доказывает, что человек
  раньше никогда не играл: истории до мониторинга нет, браузер может смениться.
- **Воронка**: открыли каталог/игру → GAME_START → GAME_OVER после старта →
  новый GAME_START после завершения на той же странице. Числа — уникальные
  браузеры, не партии. Повтор учитывается только на той же загрузке страницы;
  возвращение в другой день измеряется удержанием. GAME_START означает событие
  игры: некоторые игры отправляют его автоматически при открытии игрового поля.
- Воронка строится только по страницам, открытым в выбранном периоде **с новой
  телеметрией**. Для старых записей старты и порядок событий не восстанавливаются.
  Дата первого получения новых событий показана в отчёте. Страница, открытая
  до начала периода и продолжившая игру позже, остаётся в исходной когорте.
- Воронка по играм показывает также число страниц со стартом без полученного
  завершения. Это не точный показатель ухода: партия может продолжаться,
  а событие завершения — не доставиться.

Этапы страницы сохраняются накопительными флагами в `funnel_sessions`,
уникальными по `(user_id,session_id)`. Сервер объединяет флаги через MAX,
поэтому повторы, перестановка пакетов и переход через полночь не дублируют
страницы и не откатывают этапы. Порядок флагов проверяется при приёме.
Пакеты старого клиента без `funnel` продолжают приниматься.

CSV для компании: `/monitor/analytics.csv?kind=cohorts|games|funnel&days=14`.
Пустая ячейка процента означает, что знаменателя пока нет. Доступ — тот же
пароль отчёта. Новых персональных полей и внешних трекеров не добавлено.

## Подключение

1. Поднять отдельный сервис из этого репозитория с Root Directory
   `backend/app/monitor` (изолированные зависимости `requirements.txt`).
   **Переопределить Start Command** на
   `uvicorn main:app --host 0.0.0.0 --port $PORT`, Builder = `RAILPACK`.
   Это отдельное приложение: игровые, административные и демо-маршруты
   существующего Score Engine оно не открывает.
2. Подключить постоянный диск к сервису по пути `/data`, один экземпляр сервиса.
   SQLite подходит для пилота; при масштабировании потребуется общее хранилище.
3. Задать серверные переменные:

   | Переменная | Значение |
   |---|---|
   | `MONITOR_TOKEN` | длинный случайный пароль отчёта |
   | `MONITOR_DB_PATH` | `/data/monitor.sqlite3` |
   | `GAMEWINGO_ORIGINS` | `https://gamewingo-soz.vercel.app` |

4. По умолчанию каталог подключается к
   `https://gamewingo-monitor-production.up.railway.app`.
   Чтобы заменить сервер, в Vercel добавить **публичную** переменную сборки
   `GAMEWINGO_MONITOR_API=https://<домен сервиса>` и пересобрать каталог.
   Пароль `MONITOR_TOKEN` хранится только на сервере, в билд игры не передаётся.
5. Открыть `https://<домен сервиса>/monitor/ui`. Имя пользователя: `report`,
   пароль: `MONITOR_TOKEN`. Страница и все отчёты защищены HTTP Basic по HTTPS;
   без заданного пароля доступ всегда закрыт.

Новый сбор начинается после публикации обоих компонентов. Старый баланс
браузера не считается заработком текущего периода. Пустое значение
`GAMEWINGO_MONITOR_API` отключает мониторинг. Не размещать SQLite на файловой системе Vercel Functions:
это не постоянный диск.

## Сохранение и передача истории

Прикладная база `/data/monitor.sqlite3` находится на постоянном диске Railway.
Обновление приложения не очищает её; автоматического удаления накопленных
записей нет. Ограничения 180 дней в отчёте и при приёме очереди не являются
сроком хранения уже записанных данных.

В закрытом отчёте есть **«Вся история для передачи · ZIP»**:
`/monitor/archive.zip`, тот же логин и пароль. Архив выгружает всю накопленную
историю независимо от фильтра дат. Он содержит согласованную копию SQLite,
CSV игроков, сессий, отдельных партий, начислений и воронки, `manifest.json` с версией
формата и количеством строк, а также инструкцию по импорту. Копия создаётся
через SQLite online backup; CSV читаются из этой же копии. Пароли не включаются.
Скачивание не удаляет исходные данные. Временный файл выгрузки удаляется
после отправки.

Новый архив имеет формат версии 2 и включает `funnel_sessions.csv` и новую
таблицу в SQLite. Проверяющая задача принимает как прежние архивы версии 1,
так и версию 2; для версии 2 проверяется также количество строк воронки.
Расчёты удержания воспроизводятся по сохранённой истории активности.

Дополнительно настроена отдельная задача **gamewingo-backup**: каждые 6 часов
она скачивает полную историю по защищённому HTTPS-маршруту и загружает ZIP
в закрытый S3-совместимый bucket **gamewingo-backups**, отдельно от диска
основного сервера. Архив проверяется до загрузки и после обратного скачивания:
SHA-256, целостность ZIP, SQLite integrity_check и число строк в манифесте.
Указатель последней копии обновляется только после всех проверок. Каждая
копия имеет отдельный ключ; старые копии автоматически не удаляются.

Расписание Railway `0 */6 * * *` задаётся в UTC: **05:00, 11:00, 17:00,
23:00 по Ташкенту**, с возможной задержкой платформы. Задача завершается
после выполнения и не требует работающего компьютера. Передача архива
повторяется до трёх раз при сетевых ошибках; ошибка проверки завершает задачу
с ненулевым кодом. Логи не содержат паролей и записей игроков.

В закрытом отчёте `/monitor/backups` показывает дату и состояние последней
проверенной копии, а `/monitor/backup.zip` позволяет её скачать. После 8 часов
без успешной копии отчёт показывает предупреждение. Это предупреждение на
странице, не отдельное сообщение по почте. Статус задачи и её запусков есть
в Railway. При удалении всей учётной записи/проекта возможна потеря обоих
хранилищ: для защиты от этого скачивайте также независимую внешнюю копию.
Резервные копии ограничивают возможную потерю данных интервалом после
последней успешной копии, а не гарантируют нулевую потерю.

Для восстановления скачайте проверенный ZIP, извлеките `monitor.sqlite3`
на постоянный диск **нового** сервера и укажите `MONITOR_DB_PATH`. До переключения
сайта проверьте `PRAGMA integrity_check`, числа строк из `manifest.json`,
отчёт, историю известного игрока и сумму начислений. Не заменяйте открытую
базу работающего сервера.

### Настройка задачи резервного копирования

Исходники: `backend/app/monitor`, Builder `RAILPACK`, Start Command
`python backup.py`, Cron Schedule `0 */6 * * *`, Restart Policy `NEVER`,
без постоянного диска и публичного домена. Watch Patterns: `backup.py`
и `requirements.txt` внутри этой папки.

На задаче нужны `MONITOR_BACKUP_URL` (HTTPS-адрес монитора), `MONITOR_TOKEN`
(ссылка `${{gamewingo-monitor.MONITOR_TOKEN}}`) и следующие переменные
S3, которые также заданы основному монитору для чтения статуса/скачивания:

| Переменная приложения | Ссылка Railway |
|---|---|
| `BACKUP_S3_ENDPOINT` | `${{gamewingo-backups.ENDPOINT}}` |
| `BACKUP_S3_BUCKET` | `${{gamewingo-backups.BUCKET}}` |
| `BACKUP_S3_REGION` | `${{gamewingo-backups.REGION}}` |
| `BACKUP_S3_ACCESS_KEY_ID` | `${{gamewingo-backups.ACCESS_KEY_ID}}` |
| `BACKUP_S3_SECRET_ACCESS_KEY` | `${{gamewingo-backups.SECRET_ACCESS_KEY}}` |
| `BACKUP_S3_URL_STYLE` | `virtual` |

Пароли и ключи остаются серверными переменными, не попадают в git или игру.
Лимит одного ZIP — 1 GiB; при росте базы выше этого лимита задача явно
завершится с ошибкой, нужно перейти на другую схему/увеличить лимит.
Объём хранилища растёт с каждой копией; срок хранения пока не ограничен.
См. [Railway Cron Jobs](https://docs.railway.com/cron-jobs) и
[Storage Buckets](https://docs.railway.com/storage-buckets).

При передаче партнёру сохраняйте исходные UUID и ключи наград. Это позволяет
перенести историю и избежать повторного начисления при повторном импорте.
Анонимный UUID идентифицирует браузер, поэтому связать его с будущим
аккаунтом партнёра можно только через отдельное сопоставление при авторизации.

## Что именно измеряется

- UUID хранится в `localStorage`, одинаков для каталога и всех игр этого домена.
  Другой браузер, удаление данных или недоступный storage дают другого игрока.
- Активное время включает каталог и игры, только в видимой вкладке, без PAUSE
  от приложения и без бездействия дольше 60 секунд. После открытия/возврата
  страницы есть 60 секунд активности. Это оценка вовлечённости; несколько
  видимых вкладок могут увеличить время, заблокированный JS может его уменьшить.
- «Сейчас активны»: активный heartbeat за последние 45 секунд. Обновление
  приёмника каждые 15 секунд, отчёта — каждые 30 секунд. Это оценка, не точный
  счётчик присутствия.
- Партии считаются по `GAME_OVER` локального моста, в том числе внутри iframe.
- Коины фиксируются в момент выдачи `awardOnce` и `claimCheckin` общего
  демо-кошелька. Они не подтверждены серверным скорингом, клиент может их
  подделать. Для финансовой отчётности нужен серверный аудит реальных начислений.
- Клиентские снимки накопительные, сервер применяет максимум; награды уникальны
  по паре анонимный игрок + ключ награды. Повторная доставка не удваивает суммы.
  Данные разделены по календарным дням Ташкента, включая переход через полночь.
- При недоступной сети сохраняется очередь снимков в браузере. Доставка при
  закрытии через beacon может не пройти; следующий заход повторит очередь.
  Очередь старше 180 дней удаляется. Очистка storage, закрытие до heartbeat
  или блокировщик могут потерять данные.
- Приёмник ограничивает размер пакета, поля и даты; проверяет Origin сайта.
  Origin не является авторизацией игрока: endpoint принимает анонимную
  телеметрию. При большом публичном трафике добавить ограничение частоты на прокси.

Сбор не отправляет имя, телефон, содержимое слов/ответов, полный URL или
идентификатор банковского пользователя. IP не записывается в прикладную базу;
хостинг может вести свои HTTP-логи.

## Локальная проверка

Из `backend` после установки `requirements.txt`:

```powershell
$env:MONITOR_TOKEN = 'local-test-password'
$env:GAMEWINGO_ORIGINS = 'http://127.0.0.1:4173'
uvicorn app.monitor.main:app --host 127.0.0.1 --port 8000
```

Сборка каталога из корня: задать
`GAMEWINGO_MONITOR_API=http://127.0.0.1:8000` и выполнить `npm run build:all`.
Отчёт: `http://127.0.0.1:8000/monitor/ui`, пользователь `report`.
Тесты: `pytest tests/test_monitor.py`.
