# Локальный тест феникса

Это тестовый контур без финансовых наград и без учётной записи приложения. Искры хранит SQLite на компьютере, сервер проверяет повторы, одну игру в день и максимум три искры за день по времени Ташкента. Тестовый UUID браузера не является авторизацией; контур слушает только `127.0.0.1` и не предназначен для публикации.

## Запуск

Из корня проекта на Windows:

```powershell
uv venv .venv
uv pip install --python .venv\Scripts\python.exe -r backend\requirements.txt
npm run build:all
npm run pilot:phoenix
```

После изменений в играх повторите `npm run build:all`. Команда `pilot:phoenix` обновляет каталог и запускает оба локальных сервера. Если порты заняты, задайте `GAMEWINGO_PILOT_SITE_PORT` и `GAMEWINGO_PILOT_API_PORT` перед запуском.

Откройте `http://127.0.0.1:4173/phoenix.html?lang=ru`. На экране должно появиться «Подключено к тестовому серверу». В `http://127.0.0.1:4173/pet-pilot-check.html` кнопки имитируют итоги: первая игра даёт искру, повтор той же игры сегодня — нет, третья искра пробуждает яйцо, четвёртая за день отклоняется. Это проверка связи; затем сыграйте партии в настоящих играх каталога. Пустой забег или результат без достаточных действий искру не даёт. Проигрыш после содержательной игры может дать искру.

Имя становится доступным после шестой искры. Данные сохраняются в `backend/data/pet-pilot.sqlite3` и переживают перезапуск сервера. Разные профили браузера получают разные тестовые UUID; кнопка «Новый тестовый профиль» на диагностической странице начинает проверку с нуля без удаления старых данных. Демо-прогресс в `localStorage` не влияет на серверный.

Проверки: `.venv\Scripts\python.exe -m pytest backend/tests/test_pet_pilot.py -q --basetemp backend/data/pytest-temp`, `npm run typecheck`, `npm test --workspaces --if-present`.

Для теста внутри банковского приложения потребуется передавать в API проверенный токен игрока и развернуть постоянную базу на согласованной инфраструктуре. До этого пилот не следует включать на публичном домене или считать его награды подтверждёнными приложением.

## Тест на двух устройствах через Railway

Отдельный API `app.pet.test_app:app` использует персональные подписанные тестовые токены. Это **контур для приглашённых тестеров**, а не авторизация банковского приложения. У каждого токена свой UUID игрока; один и тот же токен на двух устройствах открывает общий прогресс. Токены действуют до 30 дней и не принимаются после истечения срока. У сервиса нет маршрута выдачи токенов, поэтому случайный посетитель не может создать себе тестовый профиль.

Сервис разворачивается отдельно от Score Engine и `gamewingo-monitor`. Для нового сервиса Railway задайте корень `/backend`, команду запуска `uvicorn app.pet.test_app:app --host 0.0.0.0 --port $PORT`, проверку здоровья `/health`, отдельный постоянный том в `/data` и переменные:

```text
GAMEWINGO_PET_DB=/data/pet.sqlite3
GAMEWINGO_PET_TEST_SECRET=<случайная строка не короче 32 байт>
GAMEWINGO_PET_TEST_ORIGINS=<точный HTTPS-адрес тестовой сборки каталога>
```

Без секрета сервис отказывается запускаться. Секрет хранится только в переменных сервиса и у оператора; его нельзя добавлять в репозиторий или статическую сборку. Резервное копирование тома нужно настроить до длительных тестов.

Для тестовой сборки каталога задайте `GAMEWINGO_PET_TEST_API=https://<домен-тестового-API>/pet` и выполните `npm run build:all`. Сборщик допускает этот режим только по явной переменной, при этом обычная сборка не содержит клиентской отправки результатов питомца. На странице `/phoenix-test.html` тестер вводит выданный токен; он хранится в `sessionStorage` этой вкладки. После этого можно открыть феникса и игры. Токен не передаётся в URL.

Выдача токена оператором из каталога `backend`:

```powershell
$env:GAMEWINGO_PET_TEST_SECRET='<тот же секрет, что у сервиса>'
python -m app.pet.test_tokens --days 14
```

Команда выводит токен. Чтобы выпустить новый токен для того же игрока, укажите `--user <UUID>`; UUID берётся из расшифрованных оператором данных, а не от клиента. Передавайте токены тестерам приватно. После теста не публикуйте результаты как награды приложения: метрики из WebView пока можно подделать, а личность тестера не связана с аккаунтом приложения.
