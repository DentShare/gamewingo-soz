# GameWingo — каталог HTML5-игр для финтеха

Контекст проекта для Claude Code. Читается автоматически в начале сессии. Держать кратким и точным.

## Что это

Каталог лёгких казуальных HTML5-игр, встраиваемых в **WebView** финтех-приложения. Игры привязаны
к баллам/наградам программы лояльности. Полная внутренняя инструкция по стеку и источникам шаблонов —
`Инструкция — стек и источники шаблонов для HTML5-игр.md` в корне.

## Стек (не менять без причины)

- **Движок:** Phaser 4 (MIT) — один движок на весь каталог.
- **Язык/сборка:** TypeScript + Vite. Официальный стартер — `template-vite-ts` (лежит в корне как `template-vite-ts-main`).
- **Хостинг:** Vercel (игра = статический билд).
- **Бэкенд:** FastAPI + Supabase (баллы, лидерборды, антифрод).
- **Связь с приложением:** WebView + JS-мост `@gamewingo/game-bridge` (`postMessage`).

## Структура репозитория

```
GameWingo/
├── CLAUDE.md                  ← этот файл
├── packages/game-bridge/      ← общий финтех-мост (@gamewingo/game-bridge)
├── games/<slug>/              ← отдельные игры (Vite-проекты) + SPEC.md на каждую
├── docs/
│   ├── SPEC.template.md        ← шаблон спеки игры
│   ├── LICENSES.md             ← реестр лицензий (обязателен)
│   └── ARCHITECTURE.md         ← схема, поток событий, правила
├── .claude/skills/            ← скиллы: new-game, license-check, fintech-bridge, webview-qa
└── <референс-репозитории>/     ← примеры (examples-master, howler.js и др.), НЕ трогать
```

## Железные правила

1. **Игра не начисляет баллы.** Отправляет `score` + `durationMs` + `sessionId`; начисление и валидация — на сервере.
2. **Антифрод на сервере:** лимит времени сессии, максимально возможный score, частота наград.
3. **Никаких реальных денег/выводов** внутри игр (App Store Guideline 4.7). Только виртуальные баллы/кэшбэк.
4. **Лицензии:** ничего под GPL/AGPL/CC-BY-NC. Каждый шаблон и ассет — строкой в `docs/LICENSES.md` до начала работы.
5. **Бюджет производительности:** билд < 5 МБ (цель < 2 МБ), загрузка < 3 сек на 3G, 60 fps на бюджетном Android.
6. **Mobile-first:** тач-управление, portrait по умолчанию. Тестировать в WebView, а не только в десктоп-браузере.

## Как делается одна игра (пайплайн)

1. Выбор шаблона по чеклисту → запись в `docs/LICENSES.md` → папка `games/<slug>` (скилл `new-game`).
2. Заполнить `games/<slug>/SPEC.md` из `docs/SPEC.template.md`.
3. Ребрендинг (ассеты Kenney/CraftPix/AI, палитра, локализация RU/UZ, сплэш).
4. Финтех-слой через `@gamewingo/game-bridge` (скилл `fintech-bridge`).
5. QA в WebView (скилл `webview-qa`) → билд на Vercel → запись в манифест каталога.

## Скиллы (использовать активно)

- **new-game** — создать новую игру из стартера, подключить мост, положить SPEC.md.
- **license-check** — прогнать кандидата по чеклисту и записать в реестр лицензий.
- **fintech-bridge** — правильно подключить события моста и серверную отправку результата.
- **webview-qa** — чеклист проверки перед сдачей (вес, fps, тач, офлайн, античит).

## Команды

```bash
npm install                              # установить зависимости всего монорепо
npm run bridge:build                     # собрать пакет моста
npm run dev  -w @gamewingo/<slug>        # запустить игру в дев-режиме
npm run build -w @gamewingo/<slug>       # прод-билд игры
npm run typecheck                        # проверка типов по всем пакетам
```

## Локализация

Все пользовательские строки — через словарь (RU/UZ, при необходимости EN). Никакого хардкода текста в сценах.
