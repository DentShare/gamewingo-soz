# GameWingo Score Engine (FastAPI)

Событийный скоринг каталога: игры шлют сырые события и финальный результат,
сервер по конфигам считает баллы, звёзды, задания и достижения и применяет
антифрод. Игра не начисляет баллы никогда (железное правило каталога №1).

## Запуск

```bash
cd backend
pip install -r requirements.txt
uvicorn app.main:app --reload          # http://127.0.0.1:8000
pytest                                  # тесты движка, антифрода и API
```

Демо-режим работает из коробки: пользователи, баланс и override-ы конфигов
живут в памяти процесса. Админка — http://127.0.0.1:8000/admin/ui,
интерактивная документация — /docs.

## Откуда берутся правила

Источник истины — TypeScript-конфиги `packages/game-progress/src/config`
(+ реальные лестницы уровней из `games/<slug>/src/core/levels.ts`).
Команда `npm run progression:export` в корне монорепо выгружает их в
`app/progression/configs/*.json`; сервер читает эти JSON. Админка может
переопределить конфиг без релиза (PUT /admin/configs/{game}) — override
приоритетнее файла.

## Эндпоинты

| Маршрут | Что делает |
|---|---|
| `POST /progression/events` | пакет сырых событий → баллы по конфигу игры |
| `POST /progression/result` | итог партии → баллы за завершение, звёзды по goals уровня, тарифы каталога (первое прохождение, слово дня), задания дня, достижения |
| `POST /progression/checkin` | чек-ин за вход: серия 5→10→…→25, пропуск дня сбрасывает |
| `GET /progression/games` | список игр с конфигами |
| `GET/PUT /admin/configs/{game}` | посмотреть/переопределить конфиг (с валидацией схемы) |
| `POST /admin/simulate/{game}` | прогноз начислений по профилю игрока |
| `POST /admin/configs/{game}/rollback` | откат к версии из истории |

## Точки боевой интеграции

- **Авторизация** — сейчас пользователь берётся из заголовка `X-User-Id`
  (демо). В проде здесь проверка JWT финтех-приложения, который игра получила
  в INIT через `@gamewingo/game-bridge` (`app/progression/router.py`).
- **Хранилище** — `InMemoryStore` заменяется реализацией того же интерфейса
  поверх Supabase; схема — `migrations/001_progression.sql` (не применена,
  прогнать вручную при выкатке).
- **Админка** — задать `ADMIN_TOKEN` в окружении; без него доступ открыт
  и годится только для локальной разработки.
- **CORS** — домены каталога в `GAMEWINGO_ORIGINS` (через запятую).

## Идемпотентность наград

Ключи выданных наград совпадают с клиентским демо-кошельком
(`packages/game-progress/src/bonus.ts`): `level-<slug>-<n>`,
`soz-daily-<dayId>`, `quest-<id>-<dayId>`, `ach-<id>`, `checkin-<dayId>`.
Повторная отправка того же результата ничего не доначисляет, а при переезде
клиента с демо-витрины на сервер игрок увидит те же цифры.
